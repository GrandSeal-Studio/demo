Flow · 开发—技术客服—运营
协作自动化平台

从需求调研、PRD、原型到落地，由我独立规划并用 AI 编程助手 + MCP 驱动开发的内部平台。它不替换 Jira，而是在 Jira 之上做自动化 + 桥接 + RAG 层：需求一键建单、Bug 流转驱动、Telegram 推送、AI 代码审查、运营工单审批、知识库问答，以及让每位成员的本地 AI 助手安全地代为读写 Jira。

9模块 01 下的 feature PRD
3仓库：doc / 后端 / 前端
11角色（含「本地 AI 代理」）

为什么要做：四类反复出现的协作痛点

来自团队日常观察与访谈，是平台的需求出发点。

开发协作

Jira 变更靠人工转发

任务/Bug 有变化，要手工复制链接到群里 @ 对应的人，漏通知、不及时。

周报

周报层层手工汇总

每人写 txt 交给整理人，再手工拼成团队周报，重复劳动。

运营—客服

后台操作口头代办

改密码、绑 IP 等靠聊天口头请求，无单据、无审批、无留痕。

文档一致性

文档与代码彼此漂移

需求、手册、设计文档、代码多轮迭代后不一致，无人核查。

全局协作流程

关键产品决策：经 Plane 本地试用（社区版功能不足、商业版超 12 席收费），保留 Jira 作为权威系统，平台只做其上的集成层。

模块与功能拆解

PRD 按「模块编号.功能编号」体系管理，PRD 只写做什么与验收标准，不写技术实现。

编号功能解决的问题
01.01即时通讯账号绑定Jira 账号 ↔ Telegram 身份映射，推送才能精准 @ 人
01.02推送规则与文案模板配置运营后台可配置哪些事件推、推给谁、文案怎么写
01.03Jira 事件推送新建 / 状态变更 / 重开 / 临近截止自动通知
01.04需求文档一键建 Jira 任务识别 PRD 中的任务，按端（前/后端）拆单并指派
01.05Bug 流转驱动修复后自动推进到验证环节并通知测试
01.06即时通讯双向操作在 Telegram 里直接改状态、评论
01.07团队周报自动汇总每周定时从 Jira 取数生成周报
01.08本地 AI 代理读写 JiraAI 以成员身份同步 Jira，白名单 + 留痕
01.09Jira 数据本地副本镜像同步，支撑报表、检索与 AI 调用

代码审查自动化

合并请求触发 AI 代码审查 → 生成结构化报告 → 推送到 Telegram，并关联对应 Jira 工作项，让 Reviewer 先看 AI 摘要再决定细看哪里。

运营工单与审批

运营在后台提交操作工单（重置密码、绑定 IP 等）→ 审核人员审批 → 系统自动执行或由技术客服执行 → 回执推送。运营按业务线隔离，全程操作留痕。

知识库问答与文档一致性

把需求文档与用户手册沉淀为可问答知识库（RAG）；定期核查文档与代码的一致性，发现差异自动建 Jira 任务跟踪。

AI 功能设计重点：本地 AI 代理读写 Jira（01.08）

让 AI 真正替人干活，同时把「越权」这个最大风险设计掉。

成员显式授权

在平台「AI 授权管理页」授权；凭证仅本地持有，随时可撤销（离职、换设备即断开）。

AI 读取分配给本人的任务

以成员本人 Jira 身份读取，权限永远不超过该成员。

工作完成后生成「事项文档」

AI 结构化列出要对哪些工作项做哪些更新（改状态 / 指派 / 评论 / 附件）。

成员逐条勾选确认（Human-in-the-loop）

只有确认过的条目才会执行，视同本人操作直接生效。

白名单执行 + 平台留痕

日志标识「来源 = 本地 AI 代理 + 实际成员」，可追溯。

操作AI 可否执行
创建 / 改状态 / 指派 / 评论 / 加附件✓ 白名单内
关闭 / 删除 / 改工作流✕ 仅人工

我怎么用 AI + MCP 开发这个项目

三个仓库都配了 CLAUDE.md、.mcp.json 与 .claude/（agents / skills / hooks），让 AI 编程助手在明确规则下工作。

flow-doc

需求与设计文档仓

平台总览、9 篇 feature PRD、调研报告、架构决策、功能依赖与开发顺序；spec → plan 两段式交给 AI 执行。

flow-boss

后端 · Hyperf / PHP

MCP：mysql（只读，禁止增删改）、context7 查文档。
Agents：PHP 审查、权限路由审计、Swoole 安全审查。
Skills：新增后台路由、新增错误码。

flow-boss-vue

前端 · Vue 3 + Element Plus

MCP：playwright 让 AI 打开浏览器自测、context7。
Skills：新建模块、Jira 导入。
Hooks：编辑后自动 ESLint、敏感文件保护。

调研 → PRD

竞品/工具调研（Jira vs Plane）后写 PRD，用质量检查清单自查，组织评审。

设计 spec → 实施 plan

把 PRD 拆成设计规格与分步计划（如列表通用态、标准时间列、系统配置框架等统一规范）。

AI 按规则编码

Claude Code 读 CLAUDE.md 与 skills 生成代码，MCP 只读查库核对数据。

AI 审查 + 自动化验收

专属 reviewer agent 审查，Playwright 跑 e2e，/review 发现的问题沉淀进 TODOS 排期。
